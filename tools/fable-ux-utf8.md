# 五 Tab 方案评审

## 1. 信息架构的问题

核心问题：你是把调试面板的条目分到了五个桶里，而不是按用户任务重新组织。

| 内容 | 现在的位置 | 问题 | 应该去哪 |
|---|---|---|---|
| 连接状态 | 相册页 | 它是全局状态，每个 Tab 都依赖它 | 每页导航栏的常驻状态胶囊（已连接 · 82%），点开是设备面板 |
| 附近设备 | 相册页 | 扫描只在首次使用或换设备时发生 | 首次引导，以及设备页的"设备管理" |
| 拍一张/录像 | 相册页 | 拍摄和取景是同一个任务，被拆到了两个 Tab | 与取景合并为"拍摄" |
| 电池/存储 | 设置页 | 状态不是设置 | 设备页顶部的状态卡；存储在相册顶部再出现一次 |
| LLM 地址/模型名 | 助手页主体 | 配一次就不动，却占着首屏 | 助手页右上角的"模型配置"二级页 |
| 诊断 | 一级 Tab | 低频功能占了五分之一的主导航 | 设备 → 高级 → 诊断 |
| 成为主人、自检 | 诊断长列表 | 和日常功能混排 | 见第 3 点 |

另外两个结构问题：

- **相册混淆了两种对象。** "眼镜里的文件"是待传输队列，"已取回到手机的"才是相册，后者有真缩略图、离线也能看。
- **没有断连状态的设计。** 每个 Tab 都要回答"眼镜不在时这页显示什么"：相册显示已导入内容，拍摄显示重连按钮，助手可以纯文字问答，设置显示缓存值并置灰。

建议改成四个 Tab：**相册 / 拍摄 / 助手 / 设备**。

## 2. 相册页

**排版**

- 按天分组（今天/昨天/3月12日），组头右侧写"8 项 · 21 MB"。
- 每行左侧是 56pt 方形占位块（照片或视频图标，灰底）。导入后原地换成本地生成的真缩略图，列表会随使用逐渐变成真相册。
- 主标题是时间（14:32），副标题是"视频 · 3.2 MB"，能拿到时长就加上。
- 行尾只放一个状态图标：下载箭头（未导入）、环形进度（传输中）、无图标（已导入）、橙色重试箭头（失败）。
- 顶部分段控件：全部 / 未导入 / 已导入。"已导入"可切成网格视图。
- 点未导入的行，导入后自动打开；点已导入的行，直接打开。
- 全程只用"导入"一个词，不要混用取回、下载、同步。

**进度与重试**

- 串行队列，一次传一条。行内显示环形进度，顶部摘要条显示总进度："正在导入 3/12 · 约剩 4 分钟"。剩余时间用实测速率算。
