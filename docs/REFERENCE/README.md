# 参考实现与协议笔记（索引）

这一组文档回答一个问题：**我们凭什么知道要发这些字节**。

内容分三类，每一条都标明出处：

- **P** = 公开协议说明（`visor.macedonga.com/protocol`，作者公开的字节级文档）；
- **R** = 参考实现的可读源码结构（Visor，AGPL-3.0；我们只读结构、不复制代码，除三份数据文件外）；
- **O** = 我们自己在真机上观测到的行为（日志行、字节长度、错误码）。

写法约定：只描述**消息长什么样、什么顺序、失败什么码**，不描述如何修改设备、如何取得额外权限。
这份文档的用途是让新接一个品牌时，能对着表填参数，而不是从零摸索。

## 怎么用这些资料

- 写代码时：`01`→`02`→`09` 是主干，遇到具体功能再看 `10`/`11`/`12`。
- 排查问题时：`05` 的样例 + 自己的日志逐字节比；对不上就先确认"长度/通道/是否带 service tag"这三件事。
- 让协作模型帮忙时：读 `PROMPTS.md`——里面把"同样的技术问题，怎么问才会被认真回答"写清楚了。

## 为什么保留这些

1. **可移植**：换平台（Android → iOS）时，能对着同一张表重写一遍，不必重新摸索。
2. **可验证**：每个常量都有出处，任何一处改动都能追到"哪份文档/哪段源码/哪行日志"。
3. **可扩展**：接第二个品牌时，先填 `04-device-profiles.md` 的六列，再看哪些服务缺失。

## 边界

- 不涉及修改设备固件、不涉及系统签名相关的内容。
- 不记录任何"取得额外权限"的方法；这里只有消息格式。
- 三份数据文件（设置目录、设置文案、助手模板）来自 Visor，AGPL-3.0，分发前需替换或授权（见 `../LICENSES.md`）。
