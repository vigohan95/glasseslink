# 05 · 报文样例

全部来自本机真机日志（**O**）。字节按原样抄写，只把密钥材料换成等长的占位符。

## 1. RequestEncryption（手机 → 眼镜，102 字节）

```
80 62 80 01 81 00 00 05 02 00 00 01  0a 40 <64B pubkey> …
```

| 段 | 内容 |
| --- | --- |
| `80 62` | 长度 `0x62` = 98，含 tag 区 |
| `80 01` | 通道 `0x8001` |
| `81 00 00 05` | tag1 = service `5`（**只有这条消息带**） |
| `02 00 00 01` | tag2 = type `1` |
| `0a 40 …` | field1（bytes，长度 0x40 = 64） |

## 2. EnableEncryption（手机 → 眼镜）

```
80 82 00 01 02 00 00 02  0a 40 <64B pubkey> 12 20 <32B seed> 1a 10 <16B IV> 20 <base> 28 1f
```

头里只有 `02 00 00 02` 一个 tag —— 没有 service tag。这一处差一个 tag，真机就整轮静默。

## 3. EndLinkSetup（加密后的第一条 DATA 帧）

明文 46 字节：

```
80 2A 80 01 02 00 10 00  08 01  12 10 <stream uuid>  1A 10 <link uuid>
```

密文帧（同一内容）：

```
40 08 <8B MAC> 02 <32B 密文>     ← 46 字节补到 48，所以 blockCount = 2（n-1 = 2 → 3 块）
```

## 4. 状态帧

```
80 04 00 01 03 00 10 00    成功（0x1000）
80 04 00 02 03 00 00 00    成功（0x0000，部分镜像通道）
80 04 00 02 03 00 C0 01    service_not_found（0xC001）
```

## 5. 一次完整的 trust 请求（114 字节）

```
80 6E 00 01 81 00 00 24 02 00 10 00  0a 20 <32B SHA256(pubkey)>  12 40 <64B r‖s>  18 02
```

| 段 | 内容 |
| --- | --- |
| `80 6E` | 长度 110 |
| `00 01` | 通道 `0x0001`（trust 走本地改名后的通道，不带 originator） |
| `81 00 00 24` | tag1 = service `36` |
| `02 00 10 00` | tag2 = type `0x1000` |
| `0a 20 …` | field1 = SHA256(公钥) |
| `12 40 …` | field2 = 签名 r‖s |
| `18 02` | field3 = 2 |

## 6. 设备回帧（经常是 116 字节的单帧）

```
80 70 80 01 81 00 00 05 02 00 00 01 …
```

与我们的 RequestEncryption 同构，只差长度与字段内容；**它只回这一条**，不回 EnableEncryption 时，说明它没接受我们那条（见样例 2）。

## 7. 从日志定位问题的顺序

1. 有没有 `sent RequestEncryption + EnableEncryption` → 我们发出去了没有；
2. 有没有 `peer … enable=present` → 它回没回第二条；
3. 有没有 `keys up — encrypted from here` → 密钥派生完成；
4. `trust ok (0x1000)` 还是 `trust rejected (0x1044)` → 签名/公钥问题，还是钥匙不匹配；
5. 一条都没有 → 链路没建立（PSM 占用、设备被别的会话连着、设备没进配对模式）。

按这五步走，不需要猜。
