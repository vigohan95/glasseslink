# 02 · DataX 帧格式

出处：**P** 公开协议说明 · **O** 真机字节。

一个 SDU 里可以放多个 DataX 消息；加密与否由通道决定（`0x8001` 与 `0x0001` 是明文控制通道，其余走 AirShield）。

## 1. 头（4 字节，大端）

```
 bit15            bit14 … bit8        bit7            bit6 … bit0
+----------------+-------------------+---------------+----------------+
| originator     |  payload 长度高 7 | hasExtension  | 长度低 7 位     |
+----------------+-------------------+---------------+----------------+
|                        channel（2 字节大端）                        |
+---------------------------------------------------------------------+
```

- `payload 长度` 是 14 位，**包含 tag 区**；
- `hasExtension`（bit7）置位时，后面还有扩展头（正常消息不用）；
- `originator`（bit15）：由发起方置位；本地分配的通道号从 `0x8002` 起并带这个位，镜像通道不带。

## 2. Tag 区

每个 tag 4 字节：

```
byte0: bit7 = 1 → 后面还有 tag；bit7 = 0 → 本 tag 是最后一个
byte1: tag id
byte2..3: 值（大端 16 位）
```

| tag id | 含义 | 出现在 |
| --- | --- | --- |
| 1 | service | 每个通道的**第一条**消息 |
| 2 | message type | 绝大多数消息 |
| 3 | error / status | 状态帧 |
| 4 | type + 关闭通道 | 结束一条通道 |
| 5 | QoS | 可选 |

**状态帧**：只有 error tag 的裸头，例如成功

```
80 04 00 01 03 00 10 00     长度 4（只有一个 tag），通道 0x0001，tag3 = 0x1000
```

## 3. 加密帧（AirShield）

```
1B  头：0x40 | stream
8B  MAC 前缀
1B  block count（n-1）
16n 密文（AES-256-CBC）
```

- MAC 输入 = `macWord(4) ‖ seq(小端 4B) ‖ blockCount ‖ 密文`，取前 8 字节；
- 填充不是 PKCS#7：`pad_len = 16 - (len % 16)`，每个填充字节的值是 `pad_len + 0xC0`；
  例：46 字节 → 补 2 字节 `C2 C2`；
- IV：第一帧用 EnableEncryption 的 field3，之后每帧取上一段密文的末块；
- `seq` 每帧 +1，永不重置（重连意味着重新握手、从对端的 base 重新开始）。

## 4. 长度解析的三个坑（都踩过）

1. **切片**：`Data` 的 `removeFirst` 只挪 `startIndex`，之后 `b[0]`/`b[9]` 会越界并触发 trap。要么重新 `Data(buf.dropFirst(n))`，要么统一按 `startIndex` 偏移。
2. **跨帧**：一条消息可以被拆成多帧，接收方要按 `4 + payloadLen` 累积，不要假设"一帧一消息"。
3. **解析失败不等于会话坏了**：短帧可能只是尾巴，记一行、跳过、继续读；直接抛错会把后面的正确帧一起丢掉。
