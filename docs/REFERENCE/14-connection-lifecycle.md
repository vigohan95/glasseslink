# 14 · 连接生命周期与高层编排

出处：**R** `core/connection/*`（37 个文件）· **O**。

这一层把"链路 + 会话 + 服务"组合成用户能感知的行为：什么时候连、连上之后跑什么、断了怎么办。
上一份（09）讲会话内部；这一份讲"谁在驱动会话"。

## 1. 文件职责

| 文件 | 职责 |
| --- | --- |
| `GlassesConnection.kt` | 连接门面：扫描、连接、断开、重连策略 |
| `GlassesState.kt` | 对外状态：未连接/连接中/握手中/就绪/失败(原因) |
| `SessionHost.kt` | 会话宿主：持有 `SecureLink`，把服务请求串行化 |
| `SessionCanary.kt` | 心跳：定期发一条无害消息确认链路还活着 |
| `Shutter.kt` | 拍摄意图（见 10） |
| `Captions.kt` | 字幕：把识别结果推给眼镜显示 |
| `Teleprompter.kt` | 提词器 |
| `Clock.kt` | 眼镜与手机的时间对齐 |
| `GlassesWifi.kt` | 把眼镜拉进 Wi-Fi、切 TCP（svc10） |
| `Nexus.kt` | 多设备聚合（多副眼镜、手机+眼镜组合） |
| `DeviceInfo.kt` | 设备信息读取（型号、固件、序列号、电量） |
| `Canary/Captions/Teleprompter` 的 UI 适配 | 各 1–3 个文件 |
| `downgrade/` | 旧固件兼容分支 |

## 2. 状态机（对 UI 只暴露这五个）

```
idle ──connect──▶ connecting ──CoC up──▶ handshaking ──trust ok──▶ ready
                     │                       │                        │
                     └────── failed(reason) ◀┴────────────────────────┘
```

`GlassesState.kt` 的 `failed` 必须带**可执行原因**，例如：

| 原因 | 建议动作 |
| --- | --- |
| `DeviceUnreachable` | 提示"眼镜可能被别的设备连着/不在配对模式"，给"重新扫描" |
| `HandshakeTimeout` | 提示"贴近眼镜后重试"，并自动重连一次 |
| `TrustRejected(0x1010)` | "这台手机没有这副眼镜的身份文件"→ 引导导入 |
| `TrustRejected(0x1042)` | "这副眼镜属于另一个账号"→ 说明不能跨账号 |
| `TrustRejected(0x1044)` | "身份文件与眼镜记录不一致"→ 重新导入或重新绑定 |

## 3. 重连策略（真实踩过的坑）

1. **不要在旧连接上重试**：CoC 打开失败后，CoreBluetooth/BlueZ 内部状态可能卡住，正确做法是拆掉整条连接、重新扫描；
2. **退避**：`already connected` 类错误要等 5–30 秒；连续失败 3 次后停止自动重连，交给用户点击；
3. **握手中途崩溃不要自动重连**：否则"崩→连→崩"会变成死循环；用一个"本次连接进行中"的标记，发现上次异常退出就只允许手动重试；
4. **眼镜会被单会话独占**：厂商应用连上会踢掉我们；同理我们连上时对方也连不进来。UI 要能解释这一点。

## 4. 心跳与时间

- `SessionCanary`：每 10–15 秒一条 status 查询；连续 3 次无响应判为假死；
- `Clock`：眼镜时间与手机时间的偏差超过 5 分钟会让 svc36 返回 `0x1045`，所以连接后先对齐；
- 眼镜电量低于约 5% 会拒绝新的拍摄会话（返回码 6）。

## 5. 多设备

`Nexus.kt` 的模型：一台手机可以记住多副眼镜（各自一份身份文件），但**同一时刻只连一副**。
切换设备的正确顺序：

```
断开当前 → 释放会话 → 选择另一副 → 用那副的身份文件握手 → 重新读设置与相册索引
```

## 6. 与 UI 的契约

UI 只依赖三样东西：

1. `GlassesState`（五个状态 + 失败原因文本）；
2. 能力位（`hasCamera` / `hasDisplay` / `hasAssistant` / `hasWifi`），据此决定显示哪些页面；
3. 服务级结果（拍摄返回 id、相册返回列表、设置返回新值）。

**不要**让 UI 直接读通道号、序列号或加解密细节——这些一旦变化，UI 不该跟着改。
